# Wiki 与覆盖维护

## 文件组织

先建立有实质内容的 `阅读首页.md`，包含版本、材料范围、核心问题、阅读模式、读者进度、已精读范围、章节导航与下一续接点。其他页面使用标准相对 Markdown 链接返回首页，兼容 Obsidian；不要指向不存在的页或用空文件修复断链。

按需创建 `全书问题与论证地图.md`、`概念索引.md`、`章节笔记/`、`专题/`、`原文/` 与 `阅读进度.md`。概念先集中，复杂概念及跨章论证再拆页。不建立没有内容的分类目录。用户批注单独分区，修改时保留；用户既有双链可保留，但检查脚本不验证双链。

## coverage.json

建立实际目录清单，不仅登记已完成单元。按范围决定是否包含序言、注释、附录，排除广告版权等非阅读内容并说明理由。以下字段为脚本检查约定：

```json
{
  "book": "书名与版本",
  "reader_progress": "读者进度未知",
  "scope": "全部可读正文及实质注释和附录",
  "next": "继续 u002 第一段",
  "units": [
    {
      "id": "u001",
      "title": "第一章 原章名",
      "status": "completed",
      "source": "原文/u001.md",
      "note": "章节笔记/001-原章名.md",
      "paragraphs": 8,
      "read_ranges": [[1, 3], [4, 8]],
      "extra_anchors": ["n001"],
      "source_locator": "EPUB spine 第3项，正文 chapter1.xhtml",
      "limitations": []
    },
    {
      "id": "u002",
      "title": "第二章 原章名",
      "status": "pending",
      "source": null,
      "note": null,
      "paragraphs": null,
      "read_ranges": [],
      "extra_anchors": [],
      "source_locator": "实际目录第二章",
      "limitations": []
    }
  ]
}
```

状态使用 `pending`、`partial`、`completed`、`blocked`。`paragraphs` 是提取后的实际正文段落数；锚点必须连续存在，不用随意拆段制造数量。`read_ranges` 记录实际已精读并写入笔记的闭区间，不能只因提取了文本就填满。注释使用额外锚点，重要注释必须进入对应分段笔记；脚本只检查其定位存在，不检查精读程度。

`completed` 要求所有正文段落范围已覆盖、来源和笔记存在，并人工确认实质注释附录已处理、关键内容无遗漏，且通过 [内容验收](depth.md#交付前的内容验收)。范围链接不能证明精读；只有简述、素材或概念标签时保持 `partial`，具体写明待补的讲解。材料缺损或公式未识别而影响理解时用 `partial` 或 `blocked`，不把补充常识当缺失原文。综合范围另在首页说明，不能用章节完成状态冒充全书综合完成。

每批更新首页、覆盖记录及必要索引；接续先读这些记录并回查相关原文，避免重复处理或跳过章节。

先完成一个真实章节的讲解并做内容回读，再采用同样深度处理后续章节。批量建立目录和提取正文可以独立进行，但不得把批量填入的摘要登记为完成。不要新增一个自动填满的“深度合格”字段代替实际判断。

## 校验与交付

运行：`python <skill目录>/scripts/check_wiki.py <书籍Wiki目录>`。

脚本检查非空首页、JSON记录、单元ID、文件、段落锚点、范围和本地 Markdown 文件／锚点链接；未完成单元给进度提示，不算结构错误。完整交付时增加 `--require-complete`，未完成单元会作为错误。Markdown 链接检查适用于标准内联链接及显式锚点、常见标题锚点；引用式链接、双链、动态内容和 Mermaid 渲染需人工核对。

脚本不验证原书目录是否完整、引文真实性、论证质量、注释精读或覆盖记录是否诚实。人工对照实际目录、来源映射及各段组，检查定义、证明、数字、证据层次和图表语义。禁止通过删除未处理单元、缩小段数或创建无实质笔记让校验通过。

交付首页路径、实际完成范围、重要疑点及下一续接点。全书完成才用完整模式检查；中途保存允许明确的未完成范围。
